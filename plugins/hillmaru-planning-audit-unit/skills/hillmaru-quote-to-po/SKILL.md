# 힐마루 견적서 → 발주서 변환

거래처 견적서(PDF)의 품목 내용을 힐마루 발주서 엑셀 템플릿의 품목표에 옮겨 넣어 발주서 파일을 완성하는 스킬.

## 전체 흐름

1. **입력 파일 확인**
   - 견적서 PDF와 발주서(양식) 엑셀 파일이 모두 있어야 한다. 하나라도 없으면 사용자에게 요청한다.
   - 발주서 엑셀은 **업체별로 발주자/공급자 정보가 이미 채워진 기존 템플릿을 재사용**하는 것이 기본 방식이다 (매번 새로 만들지 않음). 품목표만 채운다.

2. **견적서에서 품목 추출 (Claude가 직접 읽는다)**
   - 견적서 PDF를 눈으로 읽듯이 확인한다 (텍스트 추출이 되는 PDF든, 스캔본 이미지 PDF든 상관없이 — 필요하면 `/mnt/skills/public/pdf-reading/SKILL.md` 참고해서 페이지를 이미지로 렌더링해 시각적으로 읽는다). 업체마다 견적서 양식이 다르므로 스크립트로 자동 파싱하지 말고, 매번 Claude가 직접 표를 읽고 아래 규칙에 따라 정리한다.
   - 각 품목마다 다음을 추출: **품명, 규격, 수량, 단가**.
     - **단위**는 견적서에 보통 없으므로 기본값 `"EA"`를 사용한다. 견적서에 단위가 명시되어 있으면 그 값을 쓴다.
     - **공급가액**은 옮기지 않는다 — 발주서 쪽에서 단가×수량으로 자동 계산되므로 스크립트가 알아서 채운다 (아래 참고).
   - **모델명/그룹명 줄 처리** (예: "G-FLOW22"): 이런 줄은 별도 품목이 아니라 그 아래 품목들의 상위 분류다. 무시하지 말고, 하위 품목들의 품명 앞에 붙여서 합친다. 예: "G-FLOW22" 아래 "스위치" → 품명은 `"G-FLOW22 스위치"`.
   - "이 하 여백" 같은 여백 표시 줄, 소계/부가세/합계 줄은 품목이 아니므로 제외한다.
   - 추출한 품목을 `items.json`으로 정리한다 (형식은 아래 참고).

3. **발주서 품목표 채우기 (스크립트 사용)**
   - `scripts/fill_po.py`를 사용해서 발주서 템플릿에 품목을 채운다. 직접 openpyxl 코드를 즉석에서 짜지 말고 이 스크립트를 우선 사용할 것 — 헤더 자동 인식, 병합 셀 안전 처리, 수식 보존/보완 로직이 이미 검증되어 있다.
   - 사용법:
     ```bash
     python scripts/fill_po.py --template <발주서_템플릿.xlsx> --items <items.json> --output <발주서_결과.xlsx>
     ```
   - 스크립트가 하는 일:
     - 템플릿에서 "품명/규격/단위/수량/단가/공급가액" 헤더 행을 자동으로 찾는다.
     - 헤더 아래, 헤더와 같은 열 병합 패턴을 가진 연속된 행들을 "품목 입력 가능 행"으로 판단한다 (합계 요약 행처럼 병합 패턴이 바뀌면 그 앞에서 멈춘다).
     - 품명/규격/단위/수량/단가만 채우고, 공급가액 칸은 **기존 수식이 있으면 그대로 두고, 비어 있으면 `단가*수량` 수식을 새로 채워 넣는다** (아래 "알아둘 것" 참고 — 실제 템플릿에 이 버그가 있었다).
     - 그 외 셀(발주자/공급자 정보, 발주일, 합계 수식 등)은 전혀 건드리지 않는다.
     - 품목 수가 템플릿의 입력 가능 행 수보다 많으면 채우지 않고 에러를 낸다.

4. **검증**
   - 스크립트 출력의 `[검증용] 소계/부가세/합계`를 **견적서의 합계 금액과 반드시 비교**한다. 일치하지 않으면 품목 추출 단계에서 뭔가 빠졌거나 잘못 옮겨진 것이므로 다시 확인한다.
   - 품목 수가 템플릿 행 수를 초과해서 스크립트가 에러를 내면, 사용자에게 알리고 어떻게 할지 물어본다 (템플릿에 행 추가 / 발주서 분할 등). 임의로 템플릿 구조를 바꾸지 않는다.

5. **결과 전달**
   - 완성된 발주서(.xlsx)를 `/mnt/user-data/outputs/`에 저장하고 `present_files`로 전달한다.
   - 짧게 채운 품목 수와 검증용 합계를 사용자에게 알려준다 (예: "6개 품목을 16~21행에 채웠고, 합계 1,318,900원으로 견적서와 일치합니다").

## 업체별로 품목을 나눠서 여러 발주서를 만드는 경우

견적서의 전체 품목을 하나의 발주서에 다 옮기는 게 아니라, **품목별 업체 배정 표**(예: 여러 업체 견적 비교 후 품목마다 어느 업체로 발주할지 정리한 표)를 기준으로 품목을 나눠서, **업체 수만큼 발주서를 각각 만들어야 하는 경우**가 있다. 이때는 입력이 다음과 같이 늘어난다:

- 견적서 PDF 1개 이상 (업체별로 각각 있을 수 있음)
- 품목별 업체 배정 표 (엑셀/PDF/이미지 등, 보통 품목·규격·수량·단가·선정업체 컬럼 포함)
- 업체 수만큼의 발주서 템플릿 (업체별로 이미 발주자/공급자 정보가 채워진 것)

처리 순서:

1. 배정 표를 읽어서 **각 품목이 어느 업체로 배정됐는지** 파악한다. 표의 마지막 열 등에 선정업체명이 적혀 있는 경우가 많다.
2. 배정된 업체별로, 그 업체 자신의 견적서에서 해당 품목의 정확한 품명/규격/단위/수량/단가를 가져온다.
   - **주의**: 배정 표의 품목명은 업체 견적서의 품명 표기와 다를 수 있다 (예: 배정표 "아로마코스 컨디셔너(리필)" ↔ 실제 일진유통 견적서에는 "아로마코스 린스(3,000ml)"). 이름이 정확히 같지 않아도 의미상 같은 품목이면 매칭한다.
   - 같은 품목(또는 비슷한 이름의 품목)이 여러 업체 견적서에 동시에 들어있을 수 있다 (여러 업체에서 견적을 같이 받았기 때문). 이때는 **배정 표에 적힌 단가와 정확히 일치하는 업체**의 견적서 값을 써야 한다 — 단가가 일치하지 않으면 잘못된 업체의 항목을 가져온 것이니 다시 확인한다.
   - 배정 표에 있는 수량과 업체 견적서의 수량이 다르면(같은 품목이 여러 줄로 쪼개져 있는 등) 배정 표의 수량을 우선한다.
3. 업체별로 items.json을 따로 만들고, 그 업체의 발주서 템플릿에 대해 각각 `fill_po.py`를 실행한다. 템플릿마다 품목표 위치(행 번호)가 다를 수 있지만 헤더 자동 인식 로직이 알아서 처리한다.
4. **검증**: 업체별로 계산된 소계가 배정 표에 나온 그 업체의 총금액과 일치하는지 반드시 확인한다. 배정 표에 업체별 합계가 없다면, 배정된 품목들의 금액을 직접 더해서 사용자에게 알려준다.
5. 완성된 발주서를 업체 수만큼 각각 저장해서 한 번에 전달한다.

## items.json 형식

```json
[
  {"품명": "G-FLOW22 스위치", "규격": "A46210030", "단위": "EA", "수량": 10, "단가": 27000},
  {"품명": "G-FLOW22 샤프트", "규격": "A22210510", "단위": "EA", "수량": 2, "단가": 110000}
]
```

## 알아둘 것

- **공급가액 수식 누락 버그**: 실제로 사용 중인 힐마루 포천 발주서 템플릿을 확인해보니, 품목표 21행 중 앞쪽 몇 행에만 공급가액 수식(`=단가*수량`)이 들어있고 나머지는 수식 자체가 비어 있는 경우가 있었다. 이 상태로 품목을 채우면 뒤쪽 행의 금액이 합계에서 누락된다. 그래서 스크립트는 공급가액 칸이 비어 있으면 수식을 자동으로 채워 넣도록 만들어져 있다. 이 로직을 임의로 빼지 말 것.
- 발주서 템플릿마다 품목표 위치(행 번호)가 다를 수 있으므로, 하드코딩된 행 번호(예: 16~36) 대신 스크립트가 헤더 라벨을 찾아 자동으로 위치를 판단하게 되어 있다. 새로운 템플릿을 처음 다룰 때는 결과를 열어서 실제로 올바른 위치에 채워졌는지 한 번 확인하는 것이 안전하다.
- 견적서가 스캔본 이미지 PDF라 텍스트 추출이 안 되는 경우에도, Claude는 페이지를 이미지로 보고 내용을 읽을 수 있으므로 별도 OCR 도구 없이 진행 가능하다. 다만 손글씨나 화질이 나쁜 경우 숫자를 반드시 다시 한번 확인할 것 (특히 단가/수량처럼 금액에 영향을 주는 숫자).
